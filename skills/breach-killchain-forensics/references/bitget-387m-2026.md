# Worked case — Bitget $387.5M spoofed-transfer attack (Sep 2026)

Kept as the reference implementation of the methodology (Steps 1–10 of SKILL.md).
Source mix: CoinDesk (25 Sep 2026, CEO statement) → vendor IR reports (Mandiant, SlowMist, via Bitget progress reports)
→ OSINT compilation (rekt.news) → on-chain tracers (Arkham, AMLBot, Bitquery, TRM Labs, ZachXBT, Lookonchain, MistTrack)
→ vendor explainer (Halborn).

## Headline finding (the shape worth reusing)
**No private key was compromised. No cold wallet was touched. The thing that got robbed was the wallet system's trust in its own backend.**
The attacker forged the *inputs* the risk-control expected, then let Bitget's own withdrawal pipeline do the transfer — legitimately shaped, auto-approved.

## Open contradictions / unknowns (kept as findings)
- Bitget said systems *detected* unauthorised transfers at 18:31, but later said the 18:31 transfers *fired no alert* because they were below threshold — **left unexplained**.
- The third-party vendor is **never named** (only "Product A"/"Product B") by Bitget, SlowMist, or Mandiant.
- **How the attacker moved between the affected systems is still under investigation** — so the middle of the chain (appliance → wallet job server) is inference, not proof.
- Attribution: TRM found laundering-network overlap with TraderTraitor; **not definitive**. Bitget's "no common viruses or malware" is technically true and materially misleading (web shell + malicious packages + bespoke tool were found).

## Where the chain should have been cut
1. DB credentials readable via a vendor appliance's env vars → scoped secret injection, never global env vars.
2. Third-party product able to reach the production wallet job server → network segmentation; a vendor appliance must have **no route** into the wallet network.
3. Withdrawal commands verified by **origin, not proof** → per-command cryptographic authorisation from an isolated policy engine / threshold signing.
4. Risk controls sitting only on the user path → they must sit **on the money path** (between wallet job server and signer).
5. Third-party tooling must pass the same audit as first-party code — audit the vendor's tooling, not just their certificate.

## The question that gets asked wrong
*"Is the private key compromised?"* is the wrong question. The right one: **who is allowed to CONSTRUCT a withdrawal command — and with what proof?** If the answer is "anything arriving from a trusted backend", then HSM, MPC and cold storage are decoration the moment that backend turns.
